## 2. 代码接入

`miniapp/config/cloud.js` 集中维护环境名称与环境 ID。`createRoomClient({wxApi:wx})` 默认连接该环境；显式传入 envId 时按传入值连接，未确认请求仍按环境隔离保存。

开发联调页初次打开默认填写 cloud1。如果此前手动使用过别的环境，页面会保留本机保存的选择，应核对后切回 cloud1。配置环境 ID 不会自动发起调用；普通设置、答题占位页仍可独立打开。

环境 ID 不是 AppSecret。本次没有把 AppSecret、访问令牌或账号密码写入仓库。

## 3. 部署中处理的问题

首次上传时，平台先创建函数，随后因函数仍处于 Creating 状态而拒绝更新代码。确认函数转为 Active 后，使用同样的目标环境和函数名重试，得到 success=true；没有创建第二个函数或另一个环境。

微信 CLI 默认创建 Nodejs16.13，原 package.json 将最低版本写为 ≥18。核对当前依赖并使用开发者工具自带 Node.js v16.13.1，实际通过 SDK 入口加载、无身份拒绝、创建／重复请求／加入／房满／准备／退出的本地检查后，将最低版本修正为 ≥16.13，再完成部署。测试夹具使用的 structuredClone 在本次 Node 16 检查中由 v8 序列化替代，生产代码不依赖该测试函数。完整 66 项自动测试使用 Node.js v24.22.1。

这是基于实际运行环境的技术约束修正，未变更房间业务规则。正式发布前仍需评估平台推荐的运行时、依赖和超时配置，并做真实负载与冷启动测试。
