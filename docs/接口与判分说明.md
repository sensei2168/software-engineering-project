# 出题与判分：技术约定（整数四则 · 何顺）

> 范围：**整数四则**（加减乘除）的出题、作答收集、判分与计时，共 10 个设置预设。
> 混合运算、小数、分数尚未接入，会在页面上明确显示「尚未开放」，不会静默降级成别的题型。
>
> 对应计划：`docs/05_项目实施计划与分工.md` 的 P3（加减法流程）与 P4.1 的整数部分。

## 1. 支持的题型（10 / 13）

| 年级 | ruleId | 出题范围 | 状态 |
|---|---|---|---|
| 一 | `g1_add_20` | 两个 0—20 整数，和 ≤ 20 | ✅ |
| 一 | `g1_subtract_20` | 两个 0—20 整数，差 ≥ 0 | ✅ |
| 二 | `g2_add_100` | 两个 0—100 整数，和 ≤ 100 | ✅ |
| 二 | `g2_subtract_100` | 两个 0—100 整数，差 ≥ 0 | ✅ |
| 二 | `g2_multiply_table` | 两个乘数 1—9，交换乘数算重复（45 种） | ✅ |
| 二 | `g2_divide_table` | 除数、商 1—9，被除数 = 除数 × 商 | ✅ |
| 三 | `g3_add_1000` | 两个 0—1000 整数，和 ≤ 1000 | ✅ |
| 三 | `g3_subtract_1000` | 两个 0—1000 整数，差 ≥ 0 | ✅ |
| 三 | `g3_multiply_2by1` | 10—99 × 1—9 | ✅ |
| 三 | `g3_divide_2by1` | 两位数 ÷ 1—9，必须整除 | ✅ |
| 三 | `g3_mixed_2step` | 整数两步、无括号 | ⏳ 下一阶段 |
| 三 | `g3_decimal_1place` | 一位小数加减 | ⏳ 下一阶段 |
| 三 | `g3_fraction_same_den` | 同分母分数加减 | ⏳ 下一阶段 |

规则表以 `miniapp/utils/practice-rules.js` 为唯一来源；出题策略在
`miniapp/utils/question/rule-strategies.js`，两个文件的 ruleId 由测试保证一一对应。
出题器**按 ruleId 取策略**，不靠年级或 limit 猜。

> 表内乘法只有 45 种算式。设置页允许选 50 题，但答题页会提示「该范围内只有 45 种算式，请把题量调小」，
> 不会放宽范围、也不会无限重试。这是规则文档明确要求的行为。

## 2. 结构：一套逻辑，三个入口

```

│  └─ rule-strategies.js       题型 → 出题策略（范围、是否交换算重复）
├─ services/question-service.js 页面入口：云端优先，失败自动本地兜底

├─ pages/practice/             答题页
└─ cloudfunctions/createQuestionSet/
   ├─ index.js                 云函数入口（exports.main）
   ├─ practice-rules.js        与 miniapp/utils/practice-rules.js 逐字节相同
```

两端各放一份的原因：小程序端在没有云环境时也要能开发和演示；云函数端在题库/排行榜上线后作为唯一可信来源。
两边调用同一份 `handleRequest`，输入输出完全一致。改了两个目录之一**必须同步**，`tests/question.test.js`
最后一组会逐字节比对，忘记同步直接失败。

## 3. 出题规则

| 规则 | 实现方式 |
|---|---|
| 加 / 减 | 按 rule 的 `limit`（20 / 100 / 1000）构造全集 |
| 表内乘 | 两个乘数 1—9，`a <= b` 合并交换重复，共 45 种 |
| 表内除 | 除数、商 1—9，被除数 = 除数 × 商，共 81 种 |
| 两位数 × 一位数 | 10—99 × 1—9，共 810 种 |
| 两位数 ÷ 一位数 | 被除数 10—99、除数 1—9，且必须整除，共 254 种 |
| 同一次练习不重复 | 题库不大时全量洗牌取前 N 个；1000 以内加减（50 万种）改用拒绝采样 + 去重 |
| 每题字段 | `id`（会话号-序号）、`ruleId`、`text`（"7 × 8 = ?"）、`left`、`right`、`answer` |
| 确定性 | 同样的 `(ruleId, sessionId, count)` 得到同一套题；断线重连、云端重试可复现 |
| 下发给页面 | `toPublicQuestion` 去掉 `answer`；页面拿不到答案 |

加减法全集大小：`(limit+1)(limit+2)/2`，20 以内 231 种、100 以内 5151 种、1000 以内 501501 种。
乘除法题库较小，全部可以一次列出。题量上限 50，只有**表内乘法**会不够（45 种），
此时返回 `POOL_EXHAUSTED` 并提示调小题量，符合规则文档要求。

## 4. 判分规则

| 输入 | 结论 |
|---|---|
| `''`、`'   '`、`null`、`undefined` | `blank` 未答，不算错 |
| `'0'`、`0` | 参与比较，**0 是有效答案** |
| `'007'`、`' 1000 '` | 去掉首尾空格后按整数比较（最多 4 位） |
| `'abc'`、`'1.5'`、`'-3'` | `wrong`，`reason: 'invalidFormat'` |
| 与正确答案不等 | `wrong` |

汇总：`total / answered / correct / wrong / blank / accuracy / accuracyPercent`，
恒有 `correct + wrong + blank = total`、`answered = correct + wrong`，正确率 = 正确数 / 总题数。

## 5. 接口

云函数入口：`event = { action, payload }`，返回 `{ ok: true, data }` 或 `{ ok: false, code, message }`。

### 5.1 createQuestionSet

```js
// 请求
{ action: 'createQuestionSet',
  payload: { config: { grade: 1, ruleId: 'g1_subtract_20', operation: 'subtract', limit: 20,
                       count: 20, mode: 'timed', durationSeconds: 60 },
             sessionId: 'q-abc' } }

// 响应
{ ok: true, data: {
    quizId: 'q-abc',
    config: {...规范化后的设置},
    ruleVersion: '1x2y3z',      // 规则版本，历史记录用
    engineVersion: '1.2.0',
    questions: [{ id, index, ruleId, text, formula, operation, left, right }]  // 无 answer
  } }
```

规则不匹配（年级与题型不符、兼容字段被改）：`INVALID_CONFIG`。
题型尚未接入：`UNSUPPORTED_RULE`，message 形如「三年级 · 混合运算」尚未开放，请先选择整数四则运算。

### 5.2 submitAnswers

```js
// 请求：页面只交 quizId、设置和作答
{ action: 'submitAnswers',
  payload: { quizId, config, answers: ['5', '', '0'], durationSeconds: 37, finishedBy: 'manual' } }
```

本地兜底时，`question-service` 会用 `quizId` 从内存里取回「含答案的题目」再判分；
页面全程接触不到答案。`questions` 字段仍兼容（带答案的旧调用方式），但不是页面必须传的。
找不到会话：`QUIZ_NOT_FOUND`。

### 5.3 结果对象（交给结果页 / 记录页）

```js
{
  version: 1,
  quizId: 'q-abc',
  ruleId: 'g1_subtract_20',
  grade: 1,
  operation: 'subtract',
  config: { grade, ruleId, operation, limit, count, mode, durationSeconds },
  total: 4, answered: 3, correct: 2, wrong: 1, blank: 1,
  accuracy: 0.5, accuracyPercent: 50,
  durationSeconds: 37, finishedBy: 'manual',   // 或 'timeup'
  generatedAt: 1730000000000,
  questions: [{
    questionId, index, ruleId, operation, text, left, right,
    userAnswer: 5, userText: '5',        // 未答时 userAnswer 为 null
    correctAnswer: 5,
    verdict: 'correct' | 'wrong' | 'blank',
    reason: 'correct' | 'incorrect' | 'blank' | 'invalidFormat',
    correctText: '8 - 8 = 0'             // 结果页可直接展示
  }]
}
```

错误码：`INVALID_CONFIG`、`UNSUPPORTED_RULE`、`POOL_EXHAUSTED`、`INVALID_QUESTIONS`、
`ANSWER_COUNT_MISMATCH`、`QUIZ_NOT_FOUND`、`UNKNOWN_ACTION`。

## 6. 给组员的接口点

**彭方鑫（结果页）**：答题页提交成功后

1. `wx.setStorageSync('pendingPracticeResult', result)` —— 兜底；
2. `wx.navigateTo('/pages/result/result')`，在 `success` 里 `eventChannel.emit('result', result)`。

结果页接收：

```js
Page({
  onLoad() {
    const channel = this.getOpenerEventChannel && this.getOpenerEventChannel();
    if (channel && channel.on) channel.on('result', (result) => this.render(result));
    const pending = wx.getStorageSync('pendingPracticeResult');
    if (pending) this.render(pending);
  }
});
```

`result.questions[i].correctText` 已拼好 `"8 - 8 = 0"`；`ruleId` / `grade` 已包含，可直接存历史。

**闫心如（设置页）**：`practice-config.js` 的 URL 契约没改，答题页仍然用 `fromQuery` 解析，
设置页不需要改。但设置页底部「当前为设置预览…暂不生成题目」这句现在不准确了，需要改成
「确认后可开始答题」之类；`第一部分验收与手工测试用例.md` 的 T31（"只显示参数预览"）也随之失效，

## 7. 已知限制与下一步

1. **【重要】云端收卷需要服务端按 quizId 反查题目。** 本地模式靠 `question-service` 的内存会话表解决；
   云函数实例无状态，启用云环境前要把 `{quizId, questions, uid, createdAt}` 写进 `quiz_sessions` 集合，
   收卷时按 `quizId` 读取。**这是接 PK / 排行榜的前提**，否则成绩不可信。
   在此之前请保持 `CLOUD_ENV` 为空。
2. **页面级幂等**：`submitted` / `submitting` 保证一次作答只批改一次，到时自动交卷也走同一标记。
   服务端还没存结果，同一份提交发两次仍会判两次（结果相同）。记录页用 `quizId` 去重。
3. **后台计时**：以 `Date.now()` 计算剩余时间，切后台暂停刷新、回前台按真实时间差继续；
   后台停留超过时长，回前台立刻按"到时"收卷。静默杀进程后的恢复要等记录落库。
4. **计时起点**：题目加载完成、第一题出现时开始，不含出题请求耗时。
5. **剩余题型**：`g3_mixed_2step`、`g3_decimal_1place`、`g3_fraction_same_den` 还没接入。
   接入时改 `rule-strategies.js` 增加策略、`generator.js` 增加构造与答案格式：
   混合运算按优先级（先乘除后加减、同级从左到右）计算，不能用字符串 eval；
   小数用十分之一整数表示；分数用整数对判等并接受等值答案。
   这些题型的输入也更复杂（小数点、分子/分母），页面需要新的输入控件。
