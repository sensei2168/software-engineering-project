# 正式房间页与同步交付

日期：2026-11-03。组长授权接手闫心如 PR #7 后续房间工作。基线为 PR #7 的 c99f978 与 PR #6 的 e610448，保留原提交历史，解决 miniapp/README.md 的冲突。对应 DP03、DP05 和 DP07 的房间同步部分。

## 1. 完成范围

- 正式房间页复用真实 room-client：创建、加入、查询、准备、房主开赛、任一成员取消开始、退出与未确认请求重试。
- 开赛依赖服务端 capabilities.start=true、房主身份、两人准备和 waiting 阶段；缺失能力字段时保持禁用，不自动降级为模拟。
- cancelStart 与倒计时 leave 带当前 attemptId。取消保留房间和成员、清除准备；倒计时退出关闭本局。重新开赛使用后端新批次。
- 服务端 startAt／endAt 决定阶段，页面只显示剩余时间。后台、断线不延长比赛。晚到的取消、旧版本或旧批次操作刷新实际房间，不盲目重复。
- 接受 awaiting_result 并展示等待结算，不再误报断网；服务端尚未提供最终成绩时不生成胜负。
- playing 阶段显示服务端公开题目只读列表，不显示标准答案。当前练习页尚未形成比赛输入／提交接口，因此没有跳转到占位练习页，也没有做本地假提交。
- 开发／体验版独立模拟仍保留，正式版不能通过入口或参数进入模拟。

## 2. 房间同步约定

正式房间页使用单个 250 毫秒显示定时器，同时调度查询：waiting／countdown／playing 前台每 1 秒发起一次 get；awaiting_result 每 3 秒查询。查询或用户操作进行中、弹窗确认中、未确认写入尚未处理时，不再发起新的自动查询。自动查询使用独立锁，不改按钮 busy／loading 状态，也不阻挡用户点击；用户操作开始时使此前查询响应失效，旧结果或旧错误都不能覆盖新操作。真实请求延迟会拉长实际刷新周期，1 秒是调度间隔，不是同步延迟保证。

onHide 清除定时器；onShow 先恢复本机待确认请求和房间入口，再读取服务端。onUnload 不再更新页面。后台前发出的响应在返回后不用于渲染，重新读取当前状态；同一版本但服务端时间更旧的快照不能使 playing／awaiting_result 回到 countdown。

网络异常进入明确的离线界面并停止自动查询。用户重试时，有 pending 则沿用原请求编号确认原操作，没有 pending 则 get 当前房间；不自动重发写操作、不修改批次、不重置时限。页面恢复复用 PR #6 的 STALE_RESPONSE 防护。

终止房间轮询后仍可显示关闭／过期说明。ROOM_NOT_FOUND／ROOM_EXPIRED／ROOM_CLOSED 清除已失效的恢复入口，避免到期后不断查询。等待结算不视作已产生最终结果，正常离开页面后再次打开仍能恢复该房间。

彭方鑫后续继续比赛答题／结果恢复时，应复用或替换此调度入口，不叠加第二套房间轮询。当前房间页不保存任何比赛成绩，也不负责补交答案。

## 3. 接口和状态交接

| 操作／阶段 | 页面行为 |
|---|---|
| start | roomId、expectedVersion；请求编号由 room-client 保存和恢复 |
| cancelStart | roomId、expectedVersion、attemptId；成功后用返回 room 重建准备状态 |
| 倒计时 leave | 同上；必须明确确认退出；等待阶段兼容原参数 |
| MATCH_ALREADY_STARTED／ATTEMPT_MISMATCH／VERSION_CONFLICT | 刷新服务器房间并提示重新确认，不替换参数自动重发写请求 |
| countdown | 所有成员同一起点，开赛前无题目；两人均可取消，只有房主能最初启动 |
| playing | 同题只读显示，当前没有答题提交和裁判能力 |
| awaiting_result | 等待统一结算；不等于断网、结束或本机胜负 |

后续比赛答题模块需使用 roomId、attemptId、题目 id 和服务端时间，提交走可信裁判；不能把本页只读题目转成本地判分后上传分数。裁判交付后再对齐答题入口、submitAnswer／finish、本人提交恢复与最终结果协议。

正式页面操作清单如下；下方另列人工反馈，不沿用旧联调页的人工通过结论：

1. 两位成员使用同一最新版小程序和 cloud1，A 创建、B 加入；不点击刷新，观察 A 自动显示 2/2。
2. 双方准备；A 开始按钮可用，B 不可启动。A 开始后 B 自动进入同一倒计时。
3. 三秒内 B 取消，确认两端留在原房间且双方未准备。重新准备并开始，批次必须变化。
4. 再建测试局，倒计时中任一方退出，另一端显示关闭；恰好越过开赛时刻时应刷新实际阶段。
5. 开赛后三秒准备时间不扣入比赛时长；两端题目相同、顺序相同，没有标准答案。
6. 比赛到时显示等待结算，不显示断网或假成绩。退出页面再进入仍恢复等待结算。
7. 前后台切换、断网重试时不延长时间；未确认操作先用原请求重试。记录设备、账号是否不同、时间和实际结果。

## 6. 双端人工反馈与按钮闪动修复

2026-11-03，袁嘉亮按聊天中六步流程执行正式页面双端测试后反馈：“所有步骤测试通过，就是房间自动刷新会导致所有按钮都一闪一闪的”。该流程涵盖自动发现加入、准备同步、加入者取消、重新开赛同题、后台约 5 秒返回以及到时等待结算；记录为用户反馈通过，不是 AI 直接观测，也没有补填设备版本或逐项截图。上方第 4 项倒计时退出及第 7 项真实断网不包含在这六步中，仍需另测。

闪动原因是自动查询也把全页 busy 从 false 切为 true，使按钮反复禁用／启用。现已将后台 get 与用户操作分离，查询不写 busy，用户操作优先于尚未返回的查询。新增回归覆盖查询期间按钮状态不变且点击有效、旧查询错误不覆盖成功操作、卸载后旧查询不更新页面。修复后的实际视觉效果待重新编译人工确认；不改变计时、准备或开赛规则。

## 7. 等待结算返回设置

2026-11-03，根据袁嘉亮反馈增加“返回比赛设置”。仅在真实比赛 awaiting_result 阶段提供；返回后展开设置，沿用当前比赛的年级、题型、题量和时长。此操作仅切换本地入口，不调用 leave／finish，不取消云端比赛、不生成成绩。

上一场 roomId 单独保存在按环境隔离的本机存储中；设置／加入页提供“查看上一场比赛”，通过 get 恢复服务端状态。主动返回后再打开页面停留在房间入口，不自动跳回等待结算。该入口只保留最近一次主动返回的比赛，不是历史成绩列表；服务端记录到期后无法恢复。正在另一房间时不可直接切回旧场。

返回时停止轮询并使旧查询响应失效，避免晚到结果把设置页拉回等待结算。保存入口失败时留在原页面并提示，不丢失当前恢复入口。
