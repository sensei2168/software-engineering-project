# GitHub 项目记录使用说明

更新日期：2026-10-09。适用于本小组“小学口算练习微信小程序”。

仓库：[sensei2168/software-engineering-project](https://github.com/sensei2168/software-engineering-project)。已核对默认分支为 `main`，本次下载时仓库只有一份简短 README。本地整理使用 `docs/project-initiation` 分支；当前尚未将这些修改推送到 GitHub。

## 1. 各区域记录什么

| 区域 | 记录内容 | 组长要关注的内容 |
|---|---|---|
| README | 项目名称、简介、真实成员、文档及试用入口 | 新访问者能否找到项目资料 |
| docs | 立项、需求、会议、访谈、设计、测试、AI 协作记录 | 文件是否标版本、证据和待核实事项 |
| Wiki | 项目过程导航、阶段说明及关键决策 | 链接到仓库中的正式文档，避免同一正文维护两份 |
| Issues | 一项任务一条记录 | 负责人、预计完成时间、完成条件、结果证据 |
| Pull requests | 一次修改及其评审 | 修改解决哪个任务、如何核对、是否有遗漏 |

GitHub 官方说明：README 适合介绍项目，Wiki 适合展开文档；Wiki 的可用性与仓库可见性、账号方案有关。没有看到 Wiki 时先检查仓库设置和支持情况；文档仍可保存在 docs 中。参考：[关于 Wiki](https://docs.github.com/en/communities/documenting-your-project-with-wikis/about-wikis)。

立项材料仍覆盖教案要求的参会者、角色、时间、会议照片、思维导图及 NABCD 分析。

## 3. 首次提交这些资料

不熟悉命令行时，可在仓库网页使用 `Add file → Upload files`，上传桌面 `software-engineering-project` 文件夹里的 README、docs 和 .github，保留目录结构，不要上传 `.git` 文件夹。核对文件预览、补充说明，推荐创建一个分支并发起 Pull request，经组员审阅后合并到 main。

本次 README 扩展了下载时只有两行的首页。如果上传前远程内容发生变化，先比较后合并，保留组员新增内容。不要把整个“儿童学习项目立项资料”目录直接当作仓库根目录重复嵌套上传。

建议提交说明：`docs: 添加微信口算小程序立项与访谈资料`。

参考：[GitHub 官方上传文件说明](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)。本说明提供操作步骤，未代替用户点击上传或合并。

## 4. Wiki 首页建议

首页标题可用“小学口算练习微信小程序项目记录”，内容包括项目简介、当前阶段、成员分工，以及到 docs 四份文档的链接。首次提交合并到 main 后，文档地址可从 GitHub 的对应文件页面复制。

会议发生后记录参会者、角色、实际时间、讨论、决议、照片和思维导图；用链接从 Wiki 首页指向这些材料。正文以 docs 文件为准，更新正文时保留提交历史。

## 5. 可建立的首批 Issues

这些任务尚未在 GitHub 上创建。负责人和截止日期由小组按真实安排填写。

| 建议标题 | 完成条件 |
|---|---|
| 组织立项会议并明确分工 | 保存真实会议记录、照片、思维导图和分工，提交链接 |
| 联系家长并开展需求访谈 | 完成匿名访谈记录；若暂时未联系到，记录实际进展 |
| 确定纸笔与手机作答的首版范围 | 依据访谈作出决定，写明证据、取舍与未决问题 |
| 核对微信小程序账号和发布条件 | 记录核对结果、负责成员与下一步；账号密码不写进仓库 |
| 评审立项及 NABCD 草稿 | 逐项记录采纳、修改或暂缓理由，并提交更新 |
| 制作首版流程原型 | 演示配置、练习、批改与订正，收集真实反馈 |

已有任务模板 `.github/ISSUE_TEMPLATE/task.md`，合并到默认分支后可供创建任务时选用。每位成员都应留下真实完成的任务、修改或评审记录，不能只在分工表中列名字。

## 6. 简单协作约定

任务开始时补充做法；遇到阻碍时在对应任务下说明；完成时给出文档、代码或测试证据。修改通过 Pull request 关联对应任务，组员看过后再合并。不要提前把未完成的访谈、会议、测试或小程序发布标为完成。

GitHub 用来记录课程过程和源代码；产品载体仍是微信小程序。GitHub 上已有文件并不表示小程序已经公开发布。
