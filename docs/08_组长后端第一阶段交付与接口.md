## 3. 接口约定

唯一云函数名称为 `roomService`。通过微信云调用，无自定义 HTTP 地址、Authorization 请求头或 AppSecret。身份只能来自 `cloud.getWXContext()` 的 APPID、OPENID；APPID 必须是 `wxeeac1150bc72adb2`。客户端提交 OPENID、userId、分数等额外字段会被拒绝。

请求示例：

```json
{
  "action": "create",
  "requestId": "req-20261030-example-0001",
  "payload": {
    "config": { "grade": 1, "ruleId": "g1_add_20", "count": 10, "durationSeconds": 60 }
  }
}
```

| action | payload 必填字段 | 成功 data | 调用限制 |
|---|---|---|---|
| `whoami` | 空对象或省略 | `userId, appId, environmentId, stage, ruleVersion` | 可信小程序身份；不要求 requestId |
| `create` | `config` | `room, operation` | 写请求需要 requestId；比赛配置统一为 timed |
| `join` | `code` | `room, operation` | 六位数字字符串，含前导零；有效等待房间最多两人 |
| `get` | `roomId` | `room` | 仅当前成员；不要求 requestId |
| `setReady` | `roomId, expectedVersion, ready` | `room, operation` | 等待期、恰好两人、版本一致；只能改本人布尔状态 |
| `leave` | `roomId, expectedVersion` | `roomId, left:true, closed, operation` | 等待期、版本一致；加入者释放席位，房主关闭房间 |

`start`、`cancelStart`、`submitAnswer`、`finish` 返回 `FEATURE_NOT_READY`，不可据此显示已开赛或成绩。其他 action 返回 `UNKNOWN_ACTION`。

格式约束：

- `requestId`：16—96 个英文字母、数字、下划线或短横线。同一身份下每次新操作使用新编号，网络重试必须保留原编号和原参数。
- `roomId`：`r_` 加 40 位小写十六进制字符；内部标识与六位房间码不同，不可混用。
- `expectedVersion`：≥1 的安全整数，取最近一次 `get` 的 `room.version`。
- `config`：`grade` 与 `ruleId` 必须匹配现有规则；`count` 为 10—50 整数；`durationSeconds` 为 60/120/180。`mode` 可省略或为 `timed`；旧设置中的 `operation`、`limit` 可传，但必须与规则一致。表内乘法按交换去重最多 45 题，超过时返回 `QUESTION_POOL_INSUFFICIENT`。
- 所有时间为服务端 Unix 毫秒整数。客户端时钟不能延长等待期。

统一成功信封：`{ok:true, apiVersion:1, serverNow, data}`。

统一失败信封：`{ok:false, apiVersion:1, serverNow, error:{code,message}}`。`room-client` 将失败转换为带 `code` 的 Error；页面显示错误并停止对应成功流程。

`room` 示例（第二人加入后，从房主视角）：

```json
{
  "roomId": "r_0123456789012345678901234567890123456789",
  "code": "012345",
  "status": "waiting",
  "version": 2,
  "config": {
    "grade": 1, "ruleId": "g1_add_20", "ruleVersion": "2026-10-27.1",
    "count": 10, "mode": "timed", "durationSeconds": 60
  },
  "createdAt": 1800000000000,
  "expiresAt": 1800000600000,
  "attemptId": null, "startAt": null, "endAt": null,
  "selfRole": "host",
  "members": [
    { "role": "host", "ready": false, "isSelf": true },
    { "role": "guest", "ready": false, "isSelf": false }
  ]
}
```

这是格式示例，不是已部署房间。对另一成员不返回 OPENID 或内部 userId。`whoami.userId` 是 SHA-256(APPID + 冒号 + OPENID) 的稳定账号标识，仍按用户标识对待，不放入公开测试截图。

`operation` 含 `requestId, replayed, appliedVersion`。重试返回当前房间快照，`appliedVersion` 则表示原操作生效时的版本；二者可能不同，页面应渲染 `room`，不能拿旧操作重设准备状态。

## 4. 状态、并发与恢复

1. 创建：单个事务检查请求收据及房间码，写房间、码映射和收据。房主未准备，version=1，expiresAt=createdAt+10 分钟。房间码碰撞最多尝试 8 次。
2. 加入：事务核验码有效期和成员数。已有成员重复加入不增加席位或版本；新成员加入清除双方准备并增加版本。两个竞争加入请求通过事务冲突重试串行化，真实效果须云端实测。
3. 准备：先验证成员、等待阶段和 expectedVersion；只修改调用者的 ready，变化时 version+1。单人房间不能准备。
4. 加入者退出：删除本人席位，清除剩余成员准备，version+1；离开后不能再读取房间，需新的 join 操作重新进入。
5. 房主退出：状态改 cancelled、清除准备、作废对应房间码，version+1。原成员可在记录可访问期内读到关闭结果。
6. 到期：当服务端时间 ≥ expiresAt，等待房间对外显示 expired，拒绝加入／准备／退出；轮询和重连均不延长时间。此时创建新房间。
7. 网络丢响应：客户端先把写请求保存到本机，再调用云函数；未收到明确确认时保留原请求。重进页面连接同一环境后可重试，服务端以身份和 requestId 查收据，避免重复写入。
8. 版本冲突：先 `get` 刷新，用户重新确认后使用新 requestId、最新版本发送新操作。不能把旧请求编号改配新参数。

写收据、码映射和房间写入同属一个数据库事务；发生存储故障则回滚，返回 `SERVICE_UNAVAILABLE`。同一编号改参数返回 `REQUEST_CONFLICT`。SDK 事务最多重试 3 次，仍失败时由客户端保留原编号稍后重试。

页面刷新只读，不应清空成员或准备状态。当前联调页采用手动刷新；正式页面轮询、切后台暂停及返回时恢复由后续同步任务实现。双方刚好同时准备时，一方可能收到 VERSION_CONFLICT，刷新后再准备是本阶段明确的处理方式。

## 5. 数据与权限

使用同一云环境的传统文档数据库，按文档 ID 定位，不需要本阶段额外查询索引。

| 集合 | 文档 ID | 主要字段与约束 |
|---|---|---|
| `room_p2_rooms` | roomId | schemaVersion=1；status=waiting/cancelled；version 单调递增；config；members 1—2 个，host 恰好一个；createdAt/expiresAt/purgeAt；关闭时有 closedAt |
| `room_p2_codes` | 六位数字字符串 | roomId、expiresAt；只有尚未过期的映射占用房间码 |
| `room_p2_requests` | SHA-256(userId + 冒号 + requestId) | fingerprint、roomId、appliedVersion、left、closed、purgeAt；同一身份的请求编号唯一 |

members 内部保存 `userId, role, ready`。roomId 派生自创建请求键，重试稳定。fingerprint 对规范化后的 action 和 payload 计算，不受客户端 JSON 字段顺序影响。

等待房间 `purgeAt = expiresAt + 24 小时`；关闭时调整为 `closedAt + 24 小时`。到达 purgeAt 后接口拒绝访问记录或重复操作。**这是访问／重试期限，不是已实现自动物理删除**。P2 测试数据由组长在控制台清理；发布前须补充定时清理、码映射条件删除和请求保留策略，防止误删后来复用的码。

每个集合客户端权限都设置为 `{"read":false,"write":false}`；服务端管理 SDK 仍可访问，因此云函数自身必须校验成员。`database.rules.json` 是配置清单，不会因上传云函数自动生效；若环境是 PG 模式，应按该模式另行设计权限，不能直接套用本清单。

## 6. 错误处理表

| 错误码 | 页面处理 |
|---|---|
| AUTH_REQUIRED | 检查真实微信调用身份、AppID 和开发者资格，不伪造 OPENID |
| INVALID_ARGUMENT / INVALID_CONFIG / QUESTION_POOL_INSUFFICIENT | 修改输入；明确告知参数问题 |
| ROOM_NOT_FOUND / ROOM_EXPIRED / ROOM_CLOSED | 提示失效，允许重新创建或输入有效房间码 |
| ROOM_FULL / NEED_TWO_MEMBERS | 提示人数条件，不增加本地假成员 |
| NOT_MEMBER | 停止显示受保护状态；需重新加入有效房间 |
| VERSION_CONFLICT | 读取最新状态，再由用户重做操作 |
| REQUEST_CONFLICT / REQUEST_EXPIRED | 不改造原请求重试；刷新后决定新的操作 |
| ROOM_CODE_BUSY | 本次未创建，稍后新操作重试 |
| SERVICE_UNAVAILABLE | 保留请求编号，排查部署／数据库，恢复后重试 |
| CLOUD_CALL_FAILED / INVALID_RESPONSE | 未确定是否写入，保留编号并显示重试入口 |
| LOCAL_STORAGE_FAILED | 暂停新写操作，修复本机存储；已有原请求时沿用重试 |
| PENDING_REQUEST / NO_PENDING_REQUEST | 按客户端实际队列显示待确认操作或无待确认操作 |
| ENV_NOT_CONFIGURED / CLOUD_UNSUPPORTED | 核对环境 ID、基础库及工具支持 |
| FEATURE_NOT_READY / UNKNOWN_ACTION | 提示阶段未实现或接口调用错误 |

## 7. 给组员的接入方式

```js
const { createRoomClient } = require('../../utils/room-client');
// envId 由组长确定共同测试环境后提供，不要填 AppID。
const client = createRoomClient({ wxApi: wx, envId });
const response = await client.call('join', { code: '012345' });
const room = response.data.room;
// 页面保存 room；准备时传最新版本。调用失败必须进入 catch。
await client.call('setReady', { roomId: room.roomId, expectedVersion: room.version, ready: true });
// 发生网络丢响应时，提供操作按钮调用 client.retryPending()。
```

以上是调用片段，需放在 async 方法中并使用 try/catch。每个页面或同步适配层维护一个 client，按钮提交时禁用重复操作。模块已生成请求编号，页面不要另写一套随机编号重试。
