# 比赛答题、结算与订正交付

日期：2026-11-03。实现分支：`codex/match-completion`，以 PR #7 的 `18633ad` 为起点。何顺 PR #5 的修复不在本轮改动范围。

## 1. 范围与需求依据

依据第 06 份教师反馈记录、第 07 份题型与开赛规则和组长本轮接手要求，实现 DP06／DP07／DP10：13 种题型的比赛答题、服务端精确判分、提前交卷、统一结算、结果缓存与原题订正。每题答对 10 分，错／未答 0 分，同分平局；不根据网络接收快慢打破平局。这些参数沿用项目提案，不写成教师逐项确认。

`roomService` 的 whoami 阶段升级为 `p4-match-complete`，`submitAnswer` 与 `finish` 能力为 true。旧版服务能力为 false 时页面提示更新，不在客户端伪造比赛成功。

本轮不修改何顺负责的单人答题页。普通／限时练习仍需其 PR #5 修复后集成；不能把本轮比赛实现视作全部小程序已验收或已公开发布。

## 2. 接口与数据

外层格式保持 `{action,payload,requestId}`，返回 `{ok,apiVersion:1,serverNow,data}`；失败返回 `error:{code,message}`。身份只来自微信可信上下文，数据库客户端权限保持 read:false／write:false。

| 接口 | payload | 行为 |
|---|---|---|
| submitAnswer | `{roomId,attemptId,questionId,answer}` | 答案为最长24字符的字符串；要求成员、正确批次与服务端 `startAt <= now < endAt`；一次接受后锁题 |
| finish | `{roomId,attemptId}` | 锁定本人后续作答；两人交卷时结算；截止后返回已经完成的结果 |
| get | `{roomId}` | 返回当前阶段、本人已接受输入及两人的提交题数；到期时在事务中结算 |

答案与交卷不使用 expectedVersion，避免两人独立提交造成无意义的版本冲突；房间编号、批次、身份、题号和请求编号仍全部校验。开始／取消／准备继续使用原版本规则。

新状态结构：`attempt.players[] = {userId,role,answers,finishedAt}`；answers 按 questionId 保存 `{answer,correct,acceptedAt}`。这些字段仅云端内部使用。公开 `progress.self.answers` 只有题号、本人原输入和接受时间，`progress.players` 只有角色、已提交题数、是否交卷。

统一结果保存在 `attempt.result`，包括固定 `version:1`、finishedAt、reason、双方 score／correct／wrong／unanswered／accuracyText、winnerRole；平局 winnerRole 为 null。同一场只生成一次。返回 result 时额外生成本人成绩记录编号、本人胜负和本人逐题快照，绝不返回对方原始输入。

比赛截止或双方交卷前 `result:null`，公开题目仍使用白名单，不含标准答案、逐题正确性或分数。结束后本人逐题结果包含原题结构、精确标准答案、原输入和 correct／wrong／unanswered。标准答案不会通过失败信息提前泄露。

## 3. 精确判分及异常

整数与小数输入最多6位整数、6位小数；分数支持最多6位分子／分母、分母非零，也接受等值有限小数。比较使用安全整数的交叉相乘，不对输入四舍五入；`1.74` 不等于 `1.7`，`1.700` 等于 `1.7`，`2/4` 等于 `1/2`。不执行 eval，不接受科学计数法或输入算式。空输入不提交，0 是有效答案。客户端校验用于提示，最终校验与判分仍在云端。

| 错误码 | 页面处理 |
|---|---|
| INVALID_ANSWER | 保留输入并说明格式，允许修改 |
| MATCH_NOT_STARTED | 尚未开赛，刷新状态 |
| ANSWER_LOCKED／ALREADY_FINISHED | 刷新已接受的答案／交卷状态，不改答 |
| ATTEMPT_MISMATCH | 刷新当前批次，不把旧答案搬到新场 |
| MATCH_ENDED | 到时的新答案拒绝并读取最终结果 |
| CLOUD_CALL_FAILED／SERVICE_UNAVAILABLE | 保存原请求编号，明确未确认；手动重试原操作 |
| LOCAL_STORAGE_FAILED | 不发起无法保存请求编号的写操作；结果缓存失败则继续展示云端成绩并提供重试 |

事务同时写入答案／结果及成功请求回执。相同请求重试返回当前房间和原操作回执；换请求编号仍不能改已锁定答案。已接受但响应丢失的答案，到时后用原编号重试仍可确认；从未被接受的迟到答案不补分。校验时间是事务内服务端校验时间，手机时间不作为凭据。

截止后第一次查询或提交会按原截止时间生成结果，不依赖手机保持在线；没有访问时按需结算，不承诺数据库在截止瞬间主动改状态。云端访问保留24小时，逻辑到期与物理清理分别记录，不把访问拒绝说成数据已删除。

## 4. 页面与保存

- 比赛在原房间页直接答题，避免占用何顺的单人答题页。选择未提交题、填答案、确认提交，锁定后切下一题；当前页切题保留临时输入。关闭页面后仅保证恢复服务端已确认答案和未确认请求，临时输入不视为已提交。
- 前台查询沿用独立锁，不让按钮闪动，不覆盖正在输入的内容；后台停止查询，回来校时；断网不加时。最终结束停止轮询。
- 提前交卷需确认，说明未提交输入不计分。提前交卷或结束后可返回比赛设置，保留上场查看入口；直接返回首页不取消比赛。
- 最终页显示双方分数与正确率、本人逐题结果。收到云端结果后保存本机，以服务端提供的房间＋批次＋本人身份编号去重。失败如实提示并允许重试。
- 本机记录增加 kind（practice／match／correction）、match 摘要和 sourceRecordId。兼容旧记录默认值，最近100条共用上限；清除本机历史不更改云端结果。
- “订正错题与未答题”读取保存时的原题与规则版本，默认不限时；保存一条独立订正记录，不覆盖原成绩。旧记录没有结构化原题时比较保存的精确标准答案，不重新生成题目。

## 6. 双账号验收操作

1. 两端更新同一版本，选择一年级加法、10题、60秒；创建、加入、双方准备、房主开始。
2. A 提交一题正确答案、一题故意错误；B 提交一题正确。确认双方只见已提交题数，看不到对错或分数。
3. A 提前交卷，确认 A 不能继续作答、仍看不到答案；B 再提交一题正确后交卷。
4. 两端最终都应显示 A 10分、B 20分、B获胜；A 未答8题，B未答8题，各自只看到自己的逐题输入。
5. 再开一场，双方各答对一题后交卷，确认平局；再开一场到时，确认未答题计0分并统一结算。
6. 网络关闭后提交，页面显示未确认；恢复网络后重试。分别记录“请求已送达但响应丢失”和“请求未送达”，后者超时不能补分。未模拟出某一种时不要填通过。
7. 切后台5秒回来不增加时长；结束后重开页面显示相同结果，本机只有一条记录。
8. 打开本人结果，订正错题和未答题，保存为新记录；原比赛分数不变。补测小数1.74不等于1.7、等值分数2/4=1/2。
9. 返回设置、查看上一场、创建下一场；准备与输入按钮不随自动刷新闪动。
