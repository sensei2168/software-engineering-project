# R1：比赛房间草图断线恢复修复验证

日期：2026-10-28。范围：HTML交互原型；不涉及实际小程序页面和真实后端。

## 问题与修复

组长反馈两条复现路径：倒计时断线重试会变成1/2人；准备后断线重试会清空自己的准备。原实现把页面状态当作房间状态，断线时无法保存倒计时阶段，恢复又执行首次进入准备页的初始化。

修复后，独立的模拟房间快照保存成员、各自准备、阶段、开赛批次及startAt／endAt。首次切换顶部预置示例可以初始化房间，重试连接只读取已有快照。断线不会改动成员和准备；重连按原定时间展示剩余倒计时、已开赛或已结束。取消开始保留两人、清除准备并作废旧批次；关闭房间展示取消状态。两者均需明确的模拟服务端事件。

右侧新增“模拟服务端取消开始”“模拟服务端关闭房间”，用于复查断线期间的变化；这些按钮不属于正式小程序界面。准备变化和关闭、取消结果都显示事件来源，开赛后拒绝开赛前的取消／关闭行为。

## 验证方法与结果

运行：`node tests/room-reconnect.browser.cjs`，可用CHROME_PATH指定本机Chrome。

测试直接加载交互草图HTML，在Chrome的真实DOM中点击原有按钮；仅在测试页面注入可控时钟，不给正式草图增加测试专用接口，也不实际等待123秒。先用前12条用例检查原版，两条报告中的缺陷均可复现；完成修复后，18条场景全部通过。

| 场景 | 结果 |

## 复查边界

以上为浏览器原型验证，未进行真实联网、微信双端、服务端时间同步或接口竞争测试。答题和结果只显示接入位置，不生成题目、答案或成绩。正式接入时仍需校验可信身份、批次、服务端时间及取消边界，以返回的权威快照恢复；不要直接把本地模拟对象作为后端。
