# 比赛房间流程草图说明

本轮是用户第一轮分工中的页面状态草图，不修改实际小程序room页面，不接房间接口，不实现联机、身份、倒计时同步或比赛答题。全部成员、房间码与参数是演示数据。

2026-10-27 组长已确认采用本图的房主开始、3 秒倒计时、取消后留房清除双方准备规则；规范与范围见[扩展确认记录](../07_扩展题型与开赛规则确认.md)。草图的断线恢复缺陷仍待修复：倒计时重试不得回到 1/2 人，准备状态也应按原房间状态恢复。

## 页面状态与基础按钮

| 状态 | 显示内容 | 基础按钮及去向 |
| --- | --- | --- |
| 创建房间 | 比赛内容摘要 | 修改比赛设置；创建房间到等待页；输入房间码加入 |
| 输入房间码 | 六位数字输入框（格式暂定）、错误提示 | 加入房间；我来创建房间 |
| 等待另一人 | 示例房间码、1/2人、空位、比赛参数 | 复制房间码；邀请伙伴；退出房间并确认 |
| 两人准备 | 2/2人、双方准备状态 | 我准备好了／取消准备；房主开始比赛在未全部准备时禁用 |
| 双方就绪 | 双方已准备 | 房主可开始；加入者等待房主开始；可取消准备、退出 |
| 开始前倒计时 | 3、2、1和比赛摘要 | 取消开始回到双方未准备；结束后进入答题页接入位置 |
| 房间已满 | 不能加入的原因 | 重新输入房间码；创建新房间 |
| 房间失效 | 可能关闭或过期 | 重新输入房间码；创建新房间 |
| 连接失败 | 连接提示，保留原房间与设置 | 重试原连接；返回加入页面 |

开始按钮权限和准备逻辑已由组长确认：每人只控制自己准备；只有房主可开始，且双方均准备。共享比赛参数由房主创建前确定，加入者只读。倒计时为 3 秒；任一参与者开赛前可取消开始，留在原房间且双方未准备。正式起点、取消边界及重连状态由服务端统一裁定。

## 主要状态流

创建房间→等待另一人→两人准备→双方就绪→开始前倒计时→答题页接入位置。

输入房间码→查询／加入→两人准备；失败则进入已满／失效／连接失败，提供重新输入、创建或重试。

房主退出需确认并关闭房间；另一人收到关闭状态后进入失效页。准备期成员明确退出会清除准备；倒计时明确退出取消本局。“取消开始”保留两名成员但作废旧开赛批次；断线本身不取消、不退出，重连读取原房间和当前批次，不能把三者合并处理。

## 接口准备好前应与组长对齐

- 房间码长度与字符规则、有效期、人数上限（本图暂定两人和六位数字）。
- 创建、加入、退出／关闭、自己的准备切换、房主开始、取消开始、状态查询及重连的接口；取消和比赛请求关联当前开赛批次。
- 房主身份和成员权限从何处获得；不能信任客户端自行声明房主。
- 比赛复用同一 ruleId 目录，混合／小数／分数已纳入首版；实现前仍只预览，不把设置入口算成生成或裁判完成。
- 区分房满、过期、网络失败；按已确认规则同步 startAt、取消开赛批次和重连状态。

演示房间码：482731正常、111111已满、222222失效、333333连接失败。数字仅为草图演示映射，不是实际生成的房间码。复制与邀请按钮只显示说明，不写剪贴板或发送消息。

静态图分三张：01创建加入等待、02准备就绪倒计时、03异常处理。均是浏览器设计示意，不能充当微信真机成果截图。课程完整原型还需提供可交互流程、截图及可访问地址；本地草图可作为基础，后续由小组统一发布并从项目过程文档导航。
