# 云开发部署与双账号验证

更新日期：2026-10-30。适用：`codex/leader-room-backend` 分支的 P2 房间基础代码。

**当前进度：cloud1（`cloud1-d6gvp9cql29a1164e`）中的 roomService 已部署，单账号真实云调用和三个集合的客户端权限检查已通过；2026-10-30 袁嘉亮确认双账号房间基础测试五项全部通过。** 这次人工反馈包括不同身份、同房间 2/2、准备状态刷新、加入者退出清除准备和房主关闭。设备组合与版本未提供；并发、第三账号访问和真实断网恢复仍待执行。下面的准备步骤保留给组员参考，已完成的环境创建不必重复操作。

## 1. 袁嘉亮先完成的准备

1. 使用管理员微信打开开发者工具。导入本分支仓库内的 `miniapp` 文件夹，不要导入整个 Desktop 或只导入 cloudfunctions。项目 AppID 应为 `wxeeac1150bc72adb2`。
2. 点击工具中的“云开发”，查看是否已有可用环境。已有则记录环境名称、环境 ID、数据库模式、开发权限；未开通则在控制台阅读当前资源和计费说明后选择适合课程测试的配置。不承诺免费，不自动购买资源。
3. 本实现适配传统文档数据库及集合安全规则。若实际界面只有 PG 模式，先记录模式并调整存储及权限方案，不能将部署状态标为完成。
4. 环境 ID 与 AppID 不同。四人共用一个获准测试的环境，不把不同环境当作同一房间后端。组长确认协作者权限后，让至少两个不同微信账号具备开发或体验权限。
5. 当前可以使用界面完成部署，不必先开启服务端口。若希望使用 CLI 自动操作，需要本人在开发者工具“设置 → 安全设置”开启服务端口；这属于工具设置，不会替你开通云资源。

环境 ID 可给组员配置连接；AppSecret、密钥、账号密码均不放仓库。本阶段只需要平台提供的微信调用身份。

## 2. 创建集合并设置权限

在同一个测试环境数据库中创建三个集合：

- `room_p2_rooms`
- `room_p2_codes`
- `room_p2_requests`

对**每个集合分别**设置自定义客户端安全规则：

```json
{ "read": false, "write": false }
```

仓库 `miniapp/cloudfunctions/database.rules.json` 只是三个集合与规则的对应清单，不是平台自动导入文件。不要把整个清单直接粘到某一个集合的规则编辑框，不要修改无关集合。

这样客户端不能直接读写房间数据；云函数通过服务端 SDK 读写，并由代码判断调用者是否是成员。数据库规则和云函数成员校验缺一不可。记录规则截图时隐藏用户标识。

## 3. 部署云函数

1. 确认当前分支带有 `miniapp/cloudfunctions/roomService`。工具应按 `project.config.json` 中的 cloudfunctionRoot 识别云函数目录，选择刚才的环境。
2. 检查目录内有 index.js、service.js、store.js、rules.generated.json、package.json；依赖为 `wx-server-sdk` 4.0.2。本次 CLI 创建的运行时为 Nodejs16.13，已做 v16.13.1 本地兼容性检查，当前代码最低要求为 ≥16.13。
3. 右键 `roomService`，选择“上传并部署：云端安装依赖”（具体按钮以当前工具为准），等待成功。这里安装的是云函数依赖，前端不需要“构建 npm”。
4. 在云控制台核对函数名称正好为 `roomService`，部署环境正确、依赖安装成功。保留实际部署时间和版本记录。
5. 不要只在云控制台构造带 OPENID 的 JSON 当作真实调用测试；函数从可信上下文取身份，客户端伪造字段会被拒绝。下一步从小程序调用。

## 4. 打开专用联调页

1. 在开发者工具顶部编译模式中选择项目预置的“后端联调”。若没有显示，添加自定义模式，启动页面填 `pages/backend-check/backend-check`，启动参数留空，然后编译。
2. 页面标题为“共同后端验证”。首次打开会默认填入 `cloud1-d6gvp9cql29a1164e`；若本机保存了其他环境，请改回此值。点“连接并识别当前账号”，正常时显示账号标识和云端时间。
3. 甲账号点击“创建测试房间”，记下六位房间码。固定配置是“一年级加法、10 题、60 秒”，这里只保存配置，不出题或开始计时。
4. 用开发版预览或体验版，让另一个获准测试的微信账号打开同一联调页，填同一个环境 ID，连接并输入房间码。
5. 两人点“刷新房间状态”，应看到同一个 roomId、同一房间码、两名成员；各自的“我”位于不同席位。两人的身份标识应不同。同一微信在两个窗口打开不算双账号测试。
6. 依次准备，每次操作后另一端手动刷新。若同时操作遇到 VERSION_CONFLICT，刷新后再点击。

该页面只在开发版、体验版启用，首页不提供入口。体验版如果无法直达，组长与测试成员可使用开发者工具设定启动页后预览。正式房间界面由闫心如后续接入；当前不能演示答题比赛。

## 7. 遇到问题先看这里

| 提示／现象 | 处理 |
|---|---|
| `./pages/backend-check/backend-check.wxml not found` | 核对当前项目目录及分支。本机旧的 `software-engineering-project-initiation` 不包含联调页；使用 `software-engineering-project-backend/miniapp`。只把启动路径填到旧项目不会补齐页面，须打开含完整文件的项目。 |
| ENV_NOT_CONFIGURED | 填环境 ID；`wxeeac1150bc72adb2` 是 AppID，不是环境 ID |
| CLOUD_CALL_FAILED | 检查当前微信权限、网络、环境选择、函数是否部署；恢复后点原操作重试 |
| AUTH_REQUIRED | 从该 AppID 的小程序以真实微信身份调用，不能在普通网页伪造身份 |
| SERVICE_UNAVAILABLE | 查看云函数日志和三个集合是否齐全，核对 SDK、数据库模式及部署；不要靠放开客户端权限解决 |
| VERSION_CONFLICT | 刷新房间再操作，不重复覆盖旧版本 |
| PENDING_REQUEST | 先重试未确认操作，不清空请求后再连续新建 |
| 联调页显示仅用于开发版／体验版 | 检查打开的版本；正式版故意限制此入口 |

本地尚未实现：开赛与取消开赛、题目生成、倒计时、答题判分、比赛中同步、自动物理清理和发布前限流。这些仍按原计划继续，不影响本轮先验证共享房间。
