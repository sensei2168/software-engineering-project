## 1. 本轮修复

客户端可能同时保留旧页面的调用和重新进入页面后的重试。如果重试先确认，随后发起新操作，旧响应最后到达，原实现会无条件清除当前待确认请求，并更新或删除恢复房间。这可能使新操作失去安全重试入口，或让恢复入口返回旧房间。

`miniapp/utils/room-client.js` 现在在处理确认响应前，核对本机待确认请求的编号、操作和参数。只有匹配的响应才能更新恢复入口并清除该请求。旧响应返回客户端错误 `STALE_RESPONSE`，不更新缓存，也不作为成功响应交给页面渲染。服务端请求编号与接口格式不变。

三个回归用例在修改前均失败、修改后通过：旧响应不能清除新的待确认写入；旧建房响应不能覆盖新房间；旧退出响应不能删除新房间的恢复入口。既有丢响应重试、存储失败、开赛／取消恢复用例继续通过。

这次修复发生在客户端。更新本分支后重新编译小程序即可，无需重新上传 roomService。正式页面还需落实以下约定：

1. `STALE_RESPONSE` 不代表服务器撤销了操作，不再生成新请求盲目重做。
2. 先检查 `client.pending()`；有待确认请求时调用 `retryPending()`，没有时重新查询当前房间。
3. 页面销毁后忽略其回调；界面查询的过期响应与轮询生命周期仍由正式同步模块管理，本修复只保证写请求确认和恢复存储的顺序。

## 3. 可重复执行的验证工具

`scripts/cloud-room-audit.cjs` 包含检查过程；`scripts/run-cloud-room-audit.cjs` 通过微信自动化连接执行。默认不会由 npm test 发起云端操作，必须显式传入 `--run-live`。运行前开启本项目自动化端口 9431，并通过环境变量 `MINIPROGRAM_AUTOMATOR_PATH` 指向本机安装的 miniprogram-automator 模块。

```powershell
node scripts/run-cloud-room-audit.cjs --run-live
```

工具只使用当前登录账号，不获取账号密码；报告不保存身份标识和房间码。原请求前缀保存在本机忽略目录 `.artifacts/cloud-room-audit-run.json`，结果保存在 `.artifacts/cloud-room-audit.json`。正常和业务断言失败后都尝试关闭自己的房间；退出或超时不能保证关闭完成，因此上次关闭未确认时工具拒绝新建下一轮测试房间。此时先核对原请求和房间，按原编号找回并关闭，不能直接删除记录反复重跑。

本地对工具本身验证：检查流程及关闭成功、断言失败仍关闭自己的房间、不碰已有房间、旧部署在创建前被拒绝。完整本地自动检查为 **145 项通过**，题型契约检查通过。本地检查不替代上述真实云端证据。
