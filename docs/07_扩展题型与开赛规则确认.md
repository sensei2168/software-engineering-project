## 3. 首版题型和输入判定

四类整数运算继续实现；当前 13 个设置预设的完整列表见[年级题型设置交付说明](年级题型设置交付说明.md)。本轮扩展如下：

| ruleId | 题目规则 | 输入、计算与验证要求 |
|---|---|---|
| g3_mixed_2step | 三个整数、两个运算符、无括号；操作数、中间结果与最终结果均在 0—100；先乘除后加减，同级从左到右；除数非零且整除 | 整数答案；用结构化算式计算；例如 18＋6×3＝36、24÷3×2＝16，不能按字符串从左到右忽略优先级 |
| g3_decimal_1place | 一位小数的单步加／减；运算数和结果在 0—10；结果非负 | 支持小数点；内部用十分之一整数表示，避免浮点误差；例如 1.2＋0.5＝1.7；数值相等的整数和一位小数答案如 1 与 1.0 视为等值 |
| g3_fraction_same_den | 两个同分母真分数的单步加／减；分母 2—9；结果在 0—1 | 分子／分母输入，分母为正整数；接受等值分数和整数 0、1，不强制约分；例如 1/4＋1/4 的答案 2/4 与 1/2 均正确 |

小数加减、分数加减各自的每轮题目尽量均分加、减，奇数题量多一道加法。混合运算的模板与去重键以完整有序算式结构为准，不把其中某一处乘数交换等同于整题相同；单步整数加法、乘法继续按交换操作数视为重复的原规则。小数／分数单步加法同样将交换两项视为重复，减法保留顺序。

空白仍记为未答，数值 0 是有效答案。小数点不完整、分数分母为零等情况应提示输入格式错误，不伪装成合法答案。分数可以用约分后的整数对或交叉相乘判断等值，展示保留原题和用户原输入。

生成练习时保存 ruleId、规则版本、结构化原题、精确标准答案与用户答案。当前设置页的 URL 契约保留，规则版本由生成／保存层写入；历史展示不得仅依赖当前规则表重新计算旧题。比赛标准答案只存服务端，结束前不返回给客户端。

合法题库不足必须明确提示减少题量或调整规则。例如表内乘法两个乘数均为 1—9，交换乘数算重复时只有 45 道，不能满足 50 道互不重复的要求；不能无限重试或擅自放宽范围。

## 4. 采用的开赛与取消流程

1. 房主创建房间并确定题目配置，另一名独立身份加入。每人只能更改自己的准备状态。
2. 两人均准备好后，房主才能发起开始；加入者显示等待房主开始。双方准备本身不自动开赛。
3. 服务端原子检查身份、人数、准备状态、房间有效期和题库容量，生成本轮题目并设置 startAt＝就绪时的服务端当前时间＋3 秒，endAt＝startAt＋练习时长。准备题目耗时不占用儿童答题时长。
4. 两端根据同一 startAt 显示剩余倒计时。仅服务端时间达到 startAt 后才允许答题，网络延迟可能使客户端跳过部分倒计数字。
5. 倒计时尚未结束时，任一参与者可以“取消开始”：服务端取消这一开赛批次，保留房间码、配置及两名成员，清除双方准备状态，返回两人准备页。
6. 重新开始需要双方再次准备、房主再次启动，并产生新的开赛批次与统一起止时间。取消的旧批次题目、倒计时和迟到请求不得驱动新一轮。
7. “取消开始”与“退出房间”分开处理。房主开赛前退出关闭房间；加入者在等待／准备期退出释放席位并清除准备；倒计时期间任一人明确退出仍按原规则取消本局并重新创建房间。
8. 已开赛后不接受取消开始，也不暂停计时。断线本身不代表取消、退出或丢失成员；重连读取房间的当前权威状态，可能仍在倒计时、已经开始、已结束或已取消。

状态概要：

`waiting → countdown → playing → finished`

`countdown → waiting`：开赛前取消开始；保留原房间与成员、双方未准备。

`waiting → expired`：等待期限到达；`waiting／countdown → cancelled`：符合关闭房间的退出条件。

以上 waiting 同时包含一个人等待和两人准备，具体通过成员列表与准备字段区分。

### 后端实现约定

以下是落实已确认交互的技术约定，不是草图已经实现的能力：

- 用 roomId 标识房间，用 attemptId 标识每次已接受的开赛批次，用 requestId 去重开始／取消请求。重新开始换新 attemptId；重试同一开始请求不得复活已取消批次。
- 开始与取消均在服务端原子校验。取消时必须满足服务端当前时间小于 startAt；如果与开赛边界竞争，由服务端判定并返回当前状态。相同请求重试返回原处理结果，并提供当前房间状态。
- 保留原创建时间及原等待过期时间。取消开始不延长原 10 分钟等待期限；返回等待时若该期限已过，显示房间失效。
- 不依赖某台手机的定时器改变比赛状态。客户端重连不能默认回到 1/2 人，也不能擅自清除服务端仍保留的准备状态。
- 房间满员、重复身份、过期、服务端截止、已接受答案锁定、同分平局与答案保密继续按[原变更记录](06_教师反馈与需求变更记录.md)执行。
