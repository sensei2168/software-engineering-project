## 3. 何顺 PR #5 接入契约

1. `practice-config` 的配置、ruleId 与 ruleVersion 保持一致；混合运算保存 tokens，小数保存十分之一整数，分数保存分子／分母。
2. 提交结果调用 `utils/practice-session.setPendingResult(result)`，再进入 `/pages/result/result`；不要恢复旧 eventChannel／pendingResult 全局对象协议。
3. 结果至少含 practiceId、config、ruleId、ruleVersion、items；每个 item 含 expression、question、correctAnswer、userAnswer、status（correct／wrong／unanswered）。0不能当空答案。原题快照应带 answerKind 和精确答案字段，以供订正。
4. 同一练习重复提交沿用同一practiceId；保存失败不能显示已保存；手动与超时只结算一次；后台继续计时，重入不重置截止；提交失败允许恢复。
5. 本轮新增 exact-answer 与比赛裁判不会替换何顺PR5的修复。集成时检查接口和行为，通过测试后再合并，不能直接以“已提交PR”视为完成。

## 4. 验收门槛和依赖

- 本地自动测试、原生编译、页面布局通过只是开发证据；真实双账号与网络异常需另外记录。
- 两端看到相同题目与时间、同一最终分数；没有客户端上传可信分数、提前泄露答案或重复计分。
- 结果与订正可保存，关闭重开可读，原记录不覆盖；缓存失败有说明。
- 单人普通／限时必须由PR5修复集成后实际验证，当前仍是待接入依赖。
- 云端逻辑过期与物理清理、体验版与正式公开版分别验收；不能以准备好代码替代平台已部署、已审核。
- 周三中午如PR5尚未修复，立即记录为进度风险并由组长协调；未经组长进一步指示，不代改用户明确保留给何顺的修复任务。
