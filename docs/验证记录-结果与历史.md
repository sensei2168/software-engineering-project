## 检查发现与修复

| 情况 | 修复后的行为 |
|---|---|
| 开发样例入口未限制小程序版本 | 仅 develop／trial 开放；release、未知版本或版本 API 不可用时隐藏入口并拒绝直接调用 |
| 保存开发样例或旧页面重试会清掉另一份待提交结果 | 只清除与保存成功记录编号相同的待提交结果 |
| 非数组、损坏、未知版本历史可能被当成空列表覆盖 | 返回明确错误、保留原数据，阻止追加覆盖；不自动迁移未知结构 |
| 相同编号但答案或配置不同也显示已保存 | 比较不可变内容；内容冲突则失败并保留原记录；相同内容重试仍去重 |
| 保存后只检查编号，清除后不检查存储 | 保存后核对完整内容；清除后确认为空，失败不提示成功 |
| 历史详情可再次保存，可能恢复已删除记录 | 详情只读，不执行保存；历史摘要只取保存时的快照 |
| 记录规则版本与云端契约来源不同 | 统一取 `practice-rules.js` 的 `RULE_VERSION`；已明确提供的历史版本保持原值 |
| 无法序列化的原题快照被静默丢弃 | 拒绝保存并说明错误；配置同样进行序列化快照处理 |

新增 12 项回归检查；在应用修复前，新用例中 11 项复现失败，开发版／体验版正向用例通过。修复后结果与历史模块共 40 项通过。

## 给答题与批改模块的接入约定

详细示例见[小程序说明](../miniapp/README.md#与批改模块的约定)。

1. 何顺的答题模块在创建练习时固定 `practiceId`、规则版本与配置；同一练习重试不换编号、不更改内容。
2. 批改后调用 `setPendingResult`，提供每题算式、结构化原题、用户答案、正确答案和 `correct`／`wrong`／`unanswered` 状态，再进入结果页。
3. 结果页只统计已判定的状态，不承担数学判题。正确率分母包含未答题；`0` 为有效作答，漏答传空字符串。
4. 小数、分数精确答案用字符串保存，不由结果模块自行取整或约分。规则版本使用生成时固定的值。
5. 彭方鑫负责与答题模块联调，核对结果、历史快照及清除行为；结构化原题在真实接入时必须提供。当前存储兼容开发样例的缺省快照，不表示真实出题可省略它。
6. 待提交结果仅保存在当前进程内。保存失败可在当前页面重试，但关闭小程序后未保存内容可能丢失。已有异常历史保留原状，不能承诺自动恢复。
